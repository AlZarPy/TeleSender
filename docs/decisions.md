## Правило приёмки аккаунтов (11.11.2026)

Ни один купленный аккаунт не идёт в прогрев без аудита: `tools/audit_accounts.py`.
Проверяется и чистится:
- подписки с порно, казино, ставками, знакомствами — выходим (`--fix`);
- фабричные юзернеймы (`shirley_butler28`) — меняем на схему пула;
- пустое имя, нет фото — оформляем профиль;
- @SpamBot «ограничен» — в прогрев не ставим;
- нет прокси — не подключаем вообще.

Найдено на партиях 11.11: acct_c3 пришёл с чужим юзернеймом, имена Courtney/Amy/Pxydc/Gabriel —
фабричные, требуют замены. Проверка подписок на мусор — при приёмке каждой партии.

## Профиль аккаунта: только до прогрева (11.11.2026)

Правило: скрыть номер → сменить юзернейм → имя и фамилия → описание с нишей → аватарка.
Всё это ДО первого действия. Пока профиль не готов, прогрев не начинается: гейт по
`accounts.profile_ready` в `warmup.should_tick`.

Команда: `python tools/prepare_profile.py --group a --dry-run` (просмотр) и без флага (выполнение).
Скрипт ставит `profile_ready=1` сам. Проверка @SpamBot — до и после, чистка подписок — до.

## Тексты пишет Sonnet 5.5 (11.11.2026)

Любой текст для отправки — первое касание, второе сообщение, реплики в диалогах, варианты
под аккаунты — генерирует `anthropic/claude-sonnet-5.5`. Вручную на дешёвой модели тексты
не пишем. Flash остаётся для механики: код, проверки, разбор файлов.

Порядок: сгенерировать (`tools/make_launch_texts.py` / `tools/rewrite_variants.py`) →
спам-скор (`tools/antispam_score.py`) → сверка фактов (`panel/facts.py`) → согласование.

## Порядок текстов: сначала эталон, потом тираж (11.11.2026)

1. Готовится ОДИН текст А (первое касание) и ОДИН текст Б (второе, после ответа «да»).
2. Владелец утверждает слова, блоки, разметку и эмодзи.
3. Только после «утверждаю» — уникализация на все аккаунты (`tools/rewrite_variants.py`).
4. Переписанные варианты обязаны сохранять структуру: жирный заголовок, подзаголовки курсивом,
   список через «—», число блоков. Меняются слова, не скелет.

Проверка структуры встроена в `tools/rewrite_variants.py`: без разметки вариант отбрасывается.

## Пауза перед ответом — не больше 20 секунд (11.11.2026)

Правило владельца: бот отвечает быстро. Задержка «по-человечески» теперь 6–18 секунд,
редкая длинная — 12–20, жёсткий потолок — 20 секунд (`SENDERX_REPLY_DELAY_MAX=20`).
Больше не держим минуту: человек не должен ждать.

Вместе с быстрым опросом (40 секунд) полный цикл «написал → получил ответ» — до минуты.

## Цепочка А → ответ → Б работает (11.11.2026, проверено на Екатерине)

Проверка на живом чате: текст А → человек отвечает «Интересно» → текст Б с картинкой
и ссылкой приходит одним сообщением. Признано верным.

Сроки, к которым стремимся: опрос входящих 25 секунд (только аккаунты, писавшие за сутки),
пауза перед ответом 6–18 секунд (потолок 20). Итого от реплики человека до Б — до 45 секунд.

Грабли, которые ломали цепочку и стоили времени:

1. Обращение к `username` до присваивания → `UnboundLocalError` на каждом входящем,
   ошибка глоталась как «нет действий». Автоответчик молчал полностью.
2. Проверка «анонс уже отправляли» смотрела всю историю → один ошибочный анонс навсегда
   блокировал новые касания. Теперь учитывается только анонс после последнего исходящего.
3. Старые входящие принимались за свежие → Б уходил без реакции человека.
   Теперь ответ валиден только если он новее нашего последнего сообщения.
