# Промт для генерации презентации «Почтамт»

Скопируйте блок целиком в ChatGPT / Claude / Gamma / Beautiful.ai. Он самодостаточен:
в нём есть факты (чтобы модель не выдумывала цифры), структура слайдов, стиль и формат вывода.

---

## ПРОМТ

```
Ты — арт-директор и редактор презентаций уровня конференции. Твоя задача — собрать
презентацию о продукте «Почтамт» (движок рассылки SenderX + веб-панель управления).

АУДИТОРИЯ: владельцы малого бизнеса и небольшие агентства, которые уже пробовали
«серые» рассылки и обожглись банами или отсутствием отчётности. Они технически
грамотны, но не разработчики. Скепсис высокий: не верят обещаниям, верят цифрам и
деталям реализации.

ЦЕЛЬ ПРЕЗЕНТАЦИИ: за 14 слайдов показать, что рассылка может быть инженерной
дисциплиной, а не лотереей: понятный стек, измеримые ограничения, прозрачный журнал.

ТОН: спокойная уверенность инженера. Без маркетингового шума. Честность про
ограничения — часть позиционирования, а не оговорка мелким шрифтом.

═══════════════ ФАКТЫ (использовать ТОЛЬКО их) ═══════════════

Продукт:
• «Почтамт» — веб-панель; SenderX — движок рассылки под ней.
• Транспорт: MTProto через Telethon (обычный пользовательский аккаунт, не Bot API).
• Мультиаккаунт: 10–30 аккаунтов, у каждого свой прокси (SOCKS5 или MTProxy).
• Квоты на аккаунт в сутки: ориентир 15–20 для нового аккаунта, 30–50 для прогретого.
• Ротация: следующая отправка идёт через аккаунт с наибольшим остатком квоты.
• FloodWait от Telegram → аккаунт уходит в паузу на указанное время; получатель
  остаётся в очереди и уходит через другой аккаунт. Никто не теряется.
• Окна отправки и паузы с разбросом (по умолчанию 25–70 секунд) — чтобы ритм был
  человеческим, а не «бот-пулемёт».
• Журнал: каждая отправка фиксируется с результатом и причиной. Причины:
  not_found, privacy, forbidden, self, error:КлассОшибки.
• Повторный запуск не дублирует: успешные получатели пропускаются (журнал в SQLite
  и sent.jsonl).
• Диагностика канала: отдельный скрипт проверяет доступность дата-центров Telegram
  (а не только открытый api.telegram.org) — различает блокировку и троттлинг.
• Вход в аккаунты: по коду или по QR; файлы сессий не попадают в репозиторий.
• Тесты: 40 проверок без сети + 7 на фейковом клиенте (flood / privacy / not_found / self).
• Всё работает локально на своём железе: без подписки, без облака, данные не уходят
  третьим лицам.

Стек по слоям:
• транспорт — Python 3 + Telethon (MTProto), SOCKS5/MTProxy;
• движок — воркер: очередь кампаний, пул аккаунтов, квоты, обработка FloodWait;
• данные — SQLite (кампании, получатели, журнал отправок, события);
• интерфейс — FastAPI + Jinja2 + адаптивный CSS (десктоп и телефон);
• CLI-режим — те же модули без панели, для cron и отладки.

Задачи, которые решают инструменты:
• движок — доставляет сообщения, держит темп и не теряет получателей при сбоях;
• панель — делает состояние видимым: кто отправлен, кто нет и почему;
• диагностика — отвечает на вопрос «это блокировка сети или мой код»;
• журнал — даёт воспроизводимость: по любому сообщению видно аккаунт, время, причину.

Опционал сервиса (не всё сделано, часть в роадмапе — помечай честно):
• спинтаксис {вариант|вариант} и переменные имени;
• предпросмотр 5 писем до запуска и чек-лист готовности;
• авто-стоп кампании при серии ошибок;
• ловец ответов: ответивший помечается «горячий» и исключается из очереди;
• симулятор кампании: «200 получателей × лимит 20/день = 10 дней»;
• сводка о завершении кампании в Telegram;
• теги получателей, чёрный список, экспорт.

Чего продукт НЕ делает (говорить прямо):
• не парсит участников групп и не занимается инвайтингом;
• не обещает обход лимитов Telegram — лимиты первичны, продукт лишь уважает их;
• массовая рассылка незнакомым нарушает правила Telegram; риск бана лежит на владельце аккаунтов.

═══════════════ СТРУКТУРА: 14 СЛАЙДОВ ═══════════════

1. Титул. «Почтамт: рассылка, которую видно» + подзаголовок про инженерный подход.
2. Проблема. «Рассылка сегодня — чёрный ящик»: три боли (баны без объяснений,
   нет отчёта по каждому сообщению, непонятно, работает ли канал вообще).
3. Идея. «Два слоя вместо одного скрипта»: движок отвечает за доставку, панель — за правду о ней.
4. Стек. Схема из четырёх слоёв (транспорт → движок → данные → интерфейс), по одной
   строке пользы на слой.
5. Кто что решает. Таблица «инструмент → задача → что видит владелец».
6. Жизнь сообщения. Путь: список → очередь → выбор аккаунта → прокси → дата-центр →
   человек → журнал. Визуально как маршрут письма.
7. Пул аккаунтов. Почему 10–30 аккаунтов с квотами устойчивее одного «супер-аккаунта»;
   ротация по остатку и пауза при FloodWait.
8. Темп. Окна отправки, пауза 25–70 секунд, почему это выглядит по-человечески и
   почему нельзя иначе.
9. Панель. Шесть экранов + макет дашборда: квоты, кампании, журнал, события.
10. Диагностика. «Блокировка или троттлинг» — как отдельный скрипт снимает 80% ложных
    тревог; пример: DC доступны, а api.telegram.org открыт — значит канал живой.
11. Честность. Что не делаем и почему; риск-радар: «защищено / зависит от Telegram / не обещаем».
12. Опционал. Сетка из 8 карточек, каждая помечена: сделано / в роадмапе.
13. Экономика и роадмап. Локально, без подписки; стоимость = прокси + ваше время.
    Роадмап M1–M3: спинтаксис и предпросмотр → ловец ответов → симулятор и сводки.
14. Финал. «Почтамт не обещает чудес — он делает рассылку измеримой». Призыв: показать
    демо за 15 минут + QR на панель.

═══════════════ ВАУ-ЭФФЕКТ (обязательно используй) ═══════════════

• Слайд 6 оформи как «маршрут письма» — горизонтальную схему с точками-остановками.
• Слайд 11 — риск-радар: три зоны (зелёная «под контролем», жёлтая «зависит от
  Telegram», красная «сознательно не делаем»). Никакой имитации радужных обещаний.
• На слайде 9 покажи реальный макет (ASCII или нарисованный): левая колонка меню,
  справа строка «Кампания «Записка» · 18/20 · следующая через 27 с».
• Слайд 12 — «одна строка честности»: «8 возможностей: 3 работают сегодня, 5 в роадмапе».
• Добавь «микро-момент правды» на слайде 8: «Сообщение, отправленное раз в 30 секунд,
  выглядит как человек. Отправленное 20 раз в минуту — как попытка».

═══════════════ ФОРМАТ ВЫВОДА ═══════════════

Выведи три блока:
1. ДЕК (Markdown): `## Слайд N. Заголовок-утверждение`, затем 3–5 пунктов,
   затем строка `🎨 Визуал: …` и `🗣 Заметки спикера: 2–4 предложения`.
2. JSON для Gamma/Beautiful.ai:
   {"slides":[{"title":"…","bullets":["…"],"notes":"…","visual":"…"}]}
3. ОДИН СЛАЙД-КОНСПЕКТ: 5 строк для отправки в мессенджер.

═══════════════ ЗАПРЕТЫ ═══════════════

• Не выдумывать метрики, отзывы, логотипы клиентов, проценты роста. Цифры — только из
  блока ФАКТЫ.
• Слова-запреты: «инновационный», «революционный», «уникальное решение», «синергия»,
  «под ключ», «в кратчайшие сроки».
• Не обещать: «100% доставка», «обход блокировок», «без банов», «гарантия результата».
• Не использовать эмодзи в заголовках слайдов (только в служебных пометках визуала).
• Не утверждать, что функция уже есть, если она помечена «в роадмапе».

═══════════════ САМОПРОВЕРКА ПЕРЕД ВЫВОДОМ ═══════════════

Пройди по списку и исправь до выдачи:
1. Каждый заголовок — утверждение, а не тема.
2. Нет ни одной цифры, которой нет в блоке ФАКТЫ.
3. На каждом слайде ≤ 5 пунктов и ≤ 12 слов в пункте.
4. Роадмап-функции помечены как «в роадмапе».

6. Нет слов из запретного списка.

```

## Как использовать

| Инструмент | Что вставить | Что получите |
|---|---|---|
| **Gamma** | промт целиком + блок «ФОРМАТ ВЫВОДА» попросить как JSON | готовые слайды с картинками |
| **ChatGPT/Claude** | промт целиком | Markdown-дек + заметки спикера, дальше вручную в Figma/PowerPoint |
| **Beautiful.ai / Tome** | только блок «СТРУКТУРА» + стиль | быстрый черновик вёрстки |

Если нужна английская версия — добавьте в конец строку:
`Переведи финальный дек на английский, сохранив тон и запреты.`

## Что можно усилить под конкретную встречу

- **Для инвестора**: добавьте «Экономика: почему локально дешевле SaaS» и замените слайд 12 на юнит-экономику.
- **Для клиента-агентства**: добавьте слайд «Как перенести текущую базу за 10 минут» с CSV-импортом.
- **Для технической аудитории**: дайте больше схем, а слайд 10 сделайте центральным (диагностика — самая недооценённая часть).
